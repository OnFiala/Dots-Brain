# Working on Dots Brain

- Write all repository content and user-facing product text in English.
- Keep README's first paragraphs accurate about the product and release maturity.
- Commit each coherent, verified milestone with a descriptive Conventional Commit message. Push completed milestones to the authorized repository. Do not rewrite published history.
- Use semantic release versions and update the changelog when releasing.
- Keep one canonical memory store on the user's host. Never silently add hosted databases, paid APIs, telemetry, or external authentication.
- Preserve provenance, project boundaries, idempotency, and deletion behavior.
- A configured client is not a verified connection. Test actual MCP calls. Track capture separately from memory access.
- Never commit personal memories, credentials, conversation exports, model weights, or private research materials.
- Use maintained protocol libraries. Do not invent OAuth, cryptography, or provider capabilities.
- Run the relevant tests, lint, and package build before publishing a milestone. Document any checks that could not run.
- Keep the implementation small. Add a dependency only for a concrete implemented need.
- Keep functionality marked planned until it has implementation and evidence. Do not claim hidden-secret isolation when the agent can read the underlying files.
